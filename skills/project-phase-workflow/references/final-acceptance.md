# 最终验收与交付

输入为最新已确认目标、全部强制 AC、最终成果版本、相关差异及阶段证据。先确认没有遗漏的批准任务，区分实现完成、技术验证和用户体验认可。

含 OpenCode 实现时，GPT 按 [严格审阅](strict-review.md) 复核其问题闭环及关键实现；核对前端实际由 GPT 实现并检查、前后端符合现行契约，不能只凭后端任务通过宣布整体完成。整体复核核心完整流程、相关回归、数据保存与恢复、主要异常、约定的真实服务能力及安装启动。测试从要求和风险选取，不用测试总数或工作区干净代替通过条件。先前阶段证据可以复用，但后续变化影响它时补相应检查。

逐项标记 PASS / FAIL / PARTIAL / BLOCKED / NOT TESTED，并注明真实、模拟、版本及环境。所有强制项在要求的环境通过、无阻断缺陷且满足既定放行规则，才能给对应范围的通过结论。受限交付若改变原目标，先呈现已完成检查、具体缺口、影响与推荐，交用户决定。

同一聊天的检查如实称自审。单独上下文的检查说明隔离程度；用户体验认可由用户实际操作取得。没有约定必须独立验收时，不因缺少第二通道停止可执行检查。

交付提供明确成果入口、启动及必要配置、数据位置、适用的备份与恢复、错误信息入口、已知限制和维护入口。核对说明与最终成果一致，在可用环境按说明走通首次使用。敏感配置只说明名称与配置位置，不复制秘密。

对话先给结果、实际可用范围和目标差距，再按技能入口附覆盖整体强制项的验收清单，给出必要证据与文件入口。handoff 写明最终版本、验收状态、未完成事项及接续方法。结束已批准运行，不继续模型调用或自加新任务；保持用户已有业务服务，按约定停用本次专用资源。
