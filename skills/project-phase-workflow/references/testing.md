# 按影响选择测试与复用证据

阶段 0.5 安排验证、阶段 1～n 实现/修复/审阅及最终验收时按需读取。验证以有意义的改动批次为单位，覆盖本轮行为与受影响回归；测试范围由行为、依赖和风险决定，不按文件数、行数或阶段编号决定。项目已明确的强制检查及用户要求继续执行；缩减执行范围不改变验收标准，也不删改旧测试来制造通过。

## 实现与修复

先核对已有基线是否仍有效；有可复查的同版本失败证据时，优先复现原失败或必要反例，无须为每次修复再跑全量基线。基线不明、存在并发改动或环境漂移时补足所需检查，影响无法划定才扩大至全量。

普通批次检查新增/修复行为、相关正常与错误路径，以及直接或间接受影响的调用方和数据流程。共享状态、持久化、权限、并发或外部副作用即使只改一处也可能需要跨模块检查；普通说明文字、注释或局部视觉调整采用适当的内容或实际画面检查，无须默认执行无关业务测试。只修测试或辅助函数时，验证其确实能识别成功/失败及相关用例；根据运行器、公共夹具等实际影响决定是否扩大，不能仅因补证据就重跑全项目。

先跑有区分力的失败用例及相关检查，反馈稳定后再执行本批次确需的较大范围检查。同一批次可合并多个相关修改，不在每次保存、补日志或更新报告后重新开始整套验证。同一用例已被本次有效执行覆盖时可引用该结果；单独运行后又被相关套件覆盖可以用于诊断或收尾，但不为逐项生成日志重复执行，相关检查通过后仅因新变化、失败或未解决疑点追加验证。

## 扩大范围与检查点

涉及全局依赖/构建/运行配置、跨模块契约或共享基础设施，累计变更需要综合复核，局部失败暴露更广影响，或无法可靠划定影响时，扩大到相关模块、核心完整流程，必要时全量。阶段检查点覆盖本阶段 AC、受影响回归及必要核心流程；不因进入修复轮、交回验收表或阶段编号变化自动全量。最终验收覆盖全部强制 AC，结合有效阶段证据和最终综合检查完成；按既定合并、发布或综合检查点要求运行全量。全套自动检查成本低于可靠筛选成本时可直接全跑，简记理由，无须维护复杂选择器。

“全量”应指项目约定运行器、范围和环境下的整套检查，不扩展成所有真实服务、平台和长期试验。沿用批准的运行器、隔离方式及环境条件，不能用裸自动发现绕过范围限制；针对性命令也须满足相同必要初始化与隔离。真实服务、本机能力、外部模型及其他高成本检查按相关变化和约定检查点执行，不因修复无关逻辑机械重跑。不同环境可能验证不同能力，先核对实际覆盖再判断是否重复。

## 证据、审阅与派发

复用证据须可定位被测版本、范围、结果和必要环境；核对相关实现及间接依赖、配置、数据、测试/夹具与运行器的变化。无关报告或文件变化不自动使全部结果失效；受影响结论补验，其余注明沿用依据。原失败、阻塞和未测继续保留，已有失败不能以“本轮没有新增失败”标成全套 PASS；无有效证据的项目不得算通过。

审阅者检查实际差异、影响选择和测试有效性，独立复做关键验收、原失败及必要的新反例；不只复述回执，也不机械复制实现者全部命令。全套已过仍可能缺少有区分力的场景，发现新反例先针对性验证，不为每个新增探针再重跑全套。测试数量用于核对覆盖及异常减少，不能成为每次修复必须执行相同总数或持续加测的替代标准。

派发和修复意见简述本轮必验行为/相关范围、需全量时的触发理由或检查点、可沿用证据及仍开放的缺口，复用现有任务/交接即可。纠正模型自行累积的无依据全量要求，不把历史命令清单机械升级为后续每轮要求；用户明确要求的检查不得自行取消。详细日志落文件，默认读取摘要、失败/跳过及相关片段，诊断时再展开；对话验收表用于报告本轮与仍有效证据，不要求逐行重新执行。
